# Kimi 本地用量接入

读取 Kimi 桌面端内置运行时和本地 Kimi Code 的会话日志，不需要登录接口、购买会员或修改原始记录。当前验证的是 `wire.jsonl` 协议 1.4 的 `usage.record`，不承诺覆盖其他版本、网页聊天或未保存在本机的任务。

## 字段与边界

| 原始字段 | 统计含义 |
| --- | --- |
| `usage.inputOther` | 不含缓存的输入 |
| `usage.inputCacheRead` | 缓存读取输入 |
| `usage.inputCacheCreation` | 缓存创建输入 |
| `usage.output` | 输出；不额外猜测推理 Token |
| `model` | 原始模型 ID，例如 `k2d8-preview` |
| `time` | Unix 毫秒时间，展示时转北京时间 |

总输入为三个输入字段之和，总 Token 为总输入加输出。已验证的 `usageScope=turn` 记录是每次模型调用的增量，不是整轮累计数。任务后来失败不会撤销之前的用量；只有请求/报错而没有用量记录的调用不会被虚构为一次 Token 事件。

只解析顶层 `usage.record`，不把工具输出引用的日志、`contextTokens`、桌面埋点汇总再次相加。会话、agent、请求的 `turnStep`/时间与用量时间构成事件标识，重复扫描和相同会话副本会去重。实时刷新重新检查当天记录并合并，可发现延后落盘的数据；破损尾行或暂时无法读取的文件不会把历史日标记为完整。

Kimi 使用独立的来源编号 5、缓存和价格组，保留现有来源编号及用户价格顺序。实际模型费用支持按 ID 补价。未验证账户额度总量和重置边界，因此不展示 Kimi 的剩余百分比或额度周期。

`k2d8-preview` 使用 [B.AI 第三方参考价](https://docs.b.ai/llmservice/models/kimi-k2.8-preview/)（2026-09-22 核对）：每百万 Token 普通输入 $1、缓存读取 $0.25、缓存写入 $1、输出 $4。费用卡及价格来源明确标注参考估算，不代表 Kimi 官方账单或会员额度；[Kimi 官方 API 模型列表](https://platform.kimi.com/docs/models)当前未单列此模型。升级仅补齐此前未编辑的零价占位，保留用户自行填写的价格与排序，不从订阅金额反推单价。

## 2026-09-22 本地样本核对

同一任务的 16 条 `usage.record` 合计与桌面 `kimi_work_segment_complete` 埋点逐项一致：

| 项目 | Token |
| --- | ---: |
| 普通输入 | 29,562 |
| 缓存读取 | 460,288 |
| 缓存创建 | 0 |
| 总输入 | 489,850 |
| 输出 | 3,762 |
| 总计 | 493,612 |

另一个自动生成任务标题的 `ctitle-...` 会话还记录了 1 次调用：普通输入 443、缓存读取 256、输出 51，共 750 Token。全量读取当天会话时，两者都计入，因此共 **17 条 / 494,362 Token**（普通输入 30,005、缓存读取 460,544、总输入 490,549、输出 3,813）。标题生成属于真实模型用量，不能因其不是主对话而漏掉。

按上述第三方单价折算，主任务为 $0.159682，包含标题生成共 $0.160393；这些金额是参考估算，不是会员实际扣费。

第二次继续请求没有返回用量。客户端界面显示“高峰期”，本地原始错误实际为 HTTP 403 / `resource_exhausted` / `work_rate_limit_exceeded`，并提示当前计费周期额度已达上限。该错误足以确认请求被额度限制，但不能单独确定具体套餐、剩余额度或重置时刻。

任务记录显示对方已探索注册入口和日志，并定位到 `usage.record`，尚未修改仓库或编译。测试 fixture 仅保留模型、计数、时间和请求序号，不包含对话、工具输出、账户标识或凭据。

单个本地样本可支持此日志格式的实现与回放验证；持续多任务、其他客户端版本和真实恢复后的新增数据仍需后续观察。
