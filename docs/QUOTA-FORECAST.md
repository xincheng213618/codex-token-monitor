# 额度消耗预测

在周期分析的“消耗时间线”中，右侧“用量预测”提供参考区间、未来工作量、目标重置时间和模型方案选择。左图保留原始额度线，以橙色虚线表示所选方案。默认“近期预测”展示耗尽附近，避免远期目标把曲线挤在左侧；选择“预测到目标”可查看包含目标竖线的完整区间。切回“换算代价”保留原模型构成和分段表；选择与预测参数在切换时保留。

## 预测口径

- **近期实测**：参考窗口最后与最初额度点的已用百分点差，除以实际经过小时数。参考窗口可选最近 15 分钟、1 小时、3 小时或本周期；空闲计入时间。额度线本身继续使用现有快照对齐和插值结果。
- **模型普通 / Fast**：统计同一窗口的 Token 吞吐及输入、缓存、输出组成，按目标模型的订阅参考价格换算，除以该模型已有的 100% 额度容量标定。各方案假设相同 Token 工作量，不保证不同模型完成同一任务实际会用相同 Token。
- **不完整 Token 明细**：分项覆盖率至少 95% 时，按已知输入/缓存/输出比例估算少量未分类总量，来源说明显示覆盖率及此假设；低于 95% 时不提供模型方案数值。实测额度差预测不受 Token 分类缺失影响。这是数据完整性门槛，不是统计置信区间。
- **Fast**：复用 `CodexModelCost.FastQuotaMultiplier`。只增加额度消耗倍率，不额外假定模型加速会带来更多任务或更高每小时吞吐。[官方 Speed 文档](https://learn.chatgpt.com/docs/agent-configuration/speed) 于 2026-09-08 核对：Astra / GPT-5.6 / GPT-5.5 为 2.5 倍，GPT-5.4 为 2 倍。无已知倍率的模型不提供 Fast 数值。
- **未来工作量**：以参考窗口的每小时工作量为 100%，可缩减为 75%、50% 或 25%；不是每天工作时长百分比。

预测从最后一个已有额度点开始，不把该点搬到现在，也不补造当前余额。按 `剩余百分点 ÷ 预测百分点/小时` 得到假设耗尽时间；到目标时刻的剩余值限制在 0%–100%。耗尽日期按“不计重置”显示，图中预测到耗尽或目标时刻停止，不画未经发生的补满过程。

“按额度预算”的参考只在可估算的模型方案之间比较，选择能覆盖目标且剩余额度最少的方案；这不评价模型质量，也不保证官方额度行为。未覆盖目标时给出工作量需降至当前多少的预算上限。

## 数据不足与目标时间

没有两个点、真实覆盖不足 5 分钟、最后记录陈旧达到 15 分钟、历史周期、目标已过去或数据无效时暂停预测。没有额度下降时不以零斜率推断永远够用。缺 Token、价格、模型标定或 Fast 倍率时，模型方案显示不可估及原因。界面每 30 秒更新陈旧状态；“刷新数据”重新加载周期分析，避免并发重复加载。

刷新不再沿用打开窗口时固定的截止时间。`QuotaAnalysisRefreshRange` 先检查限定时间内的可信快照，确认仍是原周期后延长读取范围；发现自然到期、提前重置或同重置标识下的明确补满时，截断原周期并停止预测。缺少可信边界时保留原范围，避免将新周期 Token 合并进旧周期尾段。

“账号重置”来自原周期数据；“手动预计”只改变此次预测目标，不修改账号记录、不消耗重置卡、不切换真实模型或 Fast 设置。临时公告不写成程序规则。截图中 `6pm PST` 若实际意指夏令时 PT/PDT，与字面 PST 的北京时间有一小时差异；用户需按确认的日期和北京时间手动填写。

## 代码边界

`QuotaForecastCalculator` 为无 I/O 的 Core 计算器；`QuotaCycleUsageSample` 保存逐时 Token 标量快照，避免预测时修改原用量对象。`QuotaForecastPanel` 负责参数、状态和方案选择；`QuotaConsumptionTimelineChart.SetForecast` 只传入展示叠加层，不修改历史样本、原费用分段或几何缓存。图表范围由已有时间线视图管理。

原模型容量标定、套餐、价格配置和费用计算沿用已有口径。构建与隔离 WPF 探针保存在 `work/quota-forecast/`。
