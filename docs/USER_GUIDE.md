# Codex Token Monitor 使用指南

面向最终用户的界面操作说明。所有金额、额度百分比都是本地估算，最终以官方账单和产品页面为准。

## 1. 快速开始

1. 运行 `CodexTokenMonitor.exe`（便携版无需安装 .NET；轻量版需要 .NET 8 Desktop Runtime 和 ASP.NET Core 8 Runtime）。
2. 程序启动后自动扫描本机 Codex / Claude Code / ZCode / WorkBuddy 日志并读取额度，首次扫描较慢，之后增量读取很快。
3. 顶部左侧切换来源 Tab；右侧是“数据管理 / 重置设置 / 套餐设置 / 价格设置”。
4. 第一次使用建议先打开“价格设置”“套餐设置”“重置设置”核对默认值是否与你的实际购买一致。

## 2. 主界面

### 2.1 来源切换

五个 Tab：**Codex**、**Claude Code**、**ZCode**、**WorkBuddy**、**DSH**。每个来源独立记忆当前模式、日期和自定义起点；切换来源时会立即排入该来源刷新，没有历史缓存也会自动开始读取。只有 Codex 有额度面板。

**DSH**（DeepSeek Harness）统计你通过 dsh 命令行/网页使用 DeepSeek 模型的 token 消耗（含缓存命中），读取的是本机 `~/.dsh/sessions` 下的会话日志；主价格默认使用 DeepSeek V4.1 Flash。

**ZCode** 的数据来自 ZCode CLI 自身的持久用量库（`~/.zcode/cli/db/db.sqlite`），不受 CLI 日志轮转影响——即使 model-io 日志被重写，已发生的用量也会完整保留并自动带模型归属。该库从 2026-09-18 起有记录；更早的历史（如 6 月）由 model-io 日志回填。V4.1 Flash / V4 Pro 各保留一个合并档，程序会按每条事件的北京时间自动套用高峰或空闲价格，可在“价格设置”中调整顺序。

### 2.2 额度面板（Codex）

- **5h 额度 / 7d 额度**：本地 app-server 实时读取（或回退到会话日志捕获值）的剩余额度百分比与重置时间。
- **当前套餐**：套餐设置中覆盖当前日期的记录（名称与金额）。
- **重置过期**：尚未使用且未过期的重置卡数量与最早过期时间。
- **重置评估**：当前 7d 窗口“已用 % / 应耗 %”对比与评级。
- **[额度估算]**：打开额度估算窗口，查看当前 5h / 7d、手动额度区间和历史周期表；窗口内可按需打开额度曲线或继续分析所选周期。

### 2.3 范围选择

- 模式下拉：**天**（默认，日期选择器）/ **近 7 天**（选结束日）/ **月** / **周期**（Codex 额度 7d 周期下拉，仅 Codex）。
- **< >**：前后翻页（按当前模式：天/月翻一天/一月，7 天窗口整体平移）。
- **今天**：跳回当前。
- **从当前算**：以现在为起点向前统计（比较同一任务不同工具消耗时用）。
- **刷新日**：重建当前日缓存（删除该日缓存后重扫日志，同时预热该日额度快照与时间线）。
- **选7天**：弹出日历，选择任意结束日，自动选中其前 6 天。
- **复制摘要**：将当前来源和时间范围的 token 分类、Coding Time、前 3 个价格档费用，以及 Codex 的 5h/7d 剩余额度复制到剪贴板，方便粘贴到日报、Issue 或聊天中。

关闭程序后再次打开会先恢复上次的显示结果；DeepSeek 峰谷计价所需的峰时 token 也会一并恢复，刷新完成前费用卡不会丢失峰时价格信息。

### 2.4 汇总与指标

- **TOTAL TOKENS**：区间总 token 数；旁边按价格设置里的预设横向排列费用卡（GPT-5.6 Sol / DeepSeek V4.1 Flash / 小米 MiMo V2.5 Pro 等，可横向滚动）。
- 指标卡：Input、Cached、Cache Write、Uncached、Output、Reasoning、Cache Ratio（缓存命中率）、Events（事件数）、Coding Time（按 ≤10 分钟空闲合并会话的活跃时长）。

### 2.5 时间轴与明细表

- 时间轴：每个桶的“总 Token”与“缓存输入”柱状图 + 右轴“累计总 Token”折线；拖动时间轴与明细表之间的分隔条可调整高度。
- 明细表：按模式分桶（天=原始事件桶、周/周期=固定间隔桶、月=每日），含各 token 分类（含缓存创建）、缓存命中率、长上下文事件、估算费用与额度快照列；周/周期的额度快照会按当前 10 分钟桶对齐，不会跨到下一桶。
- 日视图和“从当前算”的汇总会从明细分桶合并完整的长上下文与峰时计价字段，费用卡不会因重建汇总而漏掉这些子统计。

周、月或周期首次查询时，如果本地只有每日汇总而没有事件明细，前台会按天补读缺失明细；如果汇总事件数大于已缓存明细数，即使旧缓存标记为完成，也会整日重扫并修复。Codex、Claude Code、ZCode、WorkBuddy 和 DSH 的首轮汇总都会与修复后的明细同步，后续查询直接命中明细缓存，不必等待后台预热完成。

当前周/月范围会叠加当天实时日志，并会随自动刷新更新；程序跨过午夜后会自动把仍在跟随当前时间的天/周/月范围滚动到新日期，主动选择的历史范围不会被改写。历史范围不会反复重扫用量，但 Codex 顶部 5h/7d 实时额度仍会独立更新。历史单日查询也遵循同样的自愈逻辑：如果已有汇总但明细事件尚未缓存，前台会在本次查询中补读明细。缓存按北京时间的自然日存储和筛选，即使内部调用使用 UTC 时间边界，也不会把事件归到前一天或后一天。

“缓存详情”中的进度会包含 token、额度和曲线缓存任务；前台查询期间即使后台状态在后台线程更新，进度按钮也会安全同步到主窗口。

## 3. 额度估算与周期分析窗口

点主界面额度面板的 **[额度估算]** 打开原额度窗口，可查看当前 5h / 7d 估算、手动指定额度区间和历史 7d 周期表。曲线不随窗口启动加载；需要时点 **[打开额度曲线]** 新开独立窗口。选中历史表中的周期后点 **[分析所选周期]**，进入该周期的模型归因、额度代价、消耗时间线与预测。主界面切到“周期”范围后，也可从周期下拉框的右键菜单进入同一分析。

- **换算代价**：按 5% 额度分段对齐本地模型记录，显示实际折算费用、100% 外推、模型构成和波动。
- **模型 100% 动态估算**：会综合同套餐全部往期周期与本期分段。往期数据按时间、样本量和一致性加权；本期不同模型混用时联合求解，极低占比模型主要沿用历史，减少偶然偏差。
- **消耗时间线**：按真实发生时间展示额度下降、分段耗时和平均消耗速度。
- **用量预测**：可比较近期实测与模型普通 / Fast 方案；数据不足、陈旧或跨重置时会停止给出不可靠预测。
- **历史周期**：在额度估算窗口集中查看历史汇总；多周期曲线按需新开，选中任一行可打开单周期分析。

## 4. 数据管理（跨电脑合并）

点击 **数据管理**：

- **导入其他电脑数据…**：选择一台或多台电脑导出的 `*.codex.json`（旧版 `*.codex-data.json` 也可）数据包，按稳定事件 ID 与快照键合并，重复导入不会重复计数。
- **导出当前明细 CSV…**：按当前来源和时间范围导出分桶明细、长上下文统计、全部费用档；Codex 当前有额度快照时也会附带 5h/7d 使用率和重置时间，生成的 UTF-8 CSV 可直接用 Excel 打开。
- **拖放导入**：将一个或多个上述数据包直接拖到主窗口，程序识别文件后会先询问是否合并。
- **仅导出今天数据… / 仅导出本周数据… / 导出全部数据…**：生成数据包。今天/本周按北京时间计算，本周从周一 00:00 起。

> 只应合并**同一个 Codex 账户**的数据；不同账户的额度百分比没有可比性。数据包不含价格、套餐、重置卡设置。

### 局域网共享（手动同步）

两台电脑都运行包含此功能的版本，打开 **数据管理 → 局域网共享…**。

1. 程序启动时默认开启共享服务，默认端口为 **36666**，可修改。将窗口显示的局域网地址和访问密钥填到另一台电脑上。
2. 在其他电脑的“连接另一台服务器”中填写地址（例如 `192.168.1.10:36666`）和访问密钥，点击 **测试连接**。
3. 第一次等两台电脑缓存完成后点击 **同步全部历史**，按日期分批双向合并。
4. 日常点击 **双向同步最近 8 天**，也可以分别上传或下载。每一步都由用户手动发起。

服务器只被动响应请求，不轮询其他电脑、不定时同步。关闭共享窗口仍保持服务；点击 **停止服务** 或退出主程序即可停止。取消 **启动程序时自动开启共享服务** 后，下次启动不再自动监听。地址、端口、自动开启选项和密钥保存在本机 `data-sharing-v1.json`，不要分享此设置文件。

上传和下载沿用文件数据包的稳定键去重，包括服务器从其他电脑合并来的记录；反复传回不会重复计数。只传输已缓存的统计事件与额度快照，不含对话、登录凭证、价格或套餐设置。若最近数据尚未缓存，先在主界面查看本周并等刷新完成。共享仅接受本周范围的数据包；跨周操作或两台电脑日期不一致时，请刷新后重试。单个数据包上限 256 MB，传输超时 3 分钟；失败、取消或结果未确认时可以重试，已成功合并的数据不会回滚或重复计数。

此功能使用 HTTP，供可信局域网或 VPN 内使用，不自动配置路由器或防火墙。连接不上时，检查服务是否已开启、地址端口是否正确，以及 Windows 防火墙是否允许该程序访问专用网络 / 该 TCP 端口。多网卡电脑会显示多个地址，选择与客户端可互通的地址。

## 5. 价格设置

Codex 主界面的“标准 API 等价”按实际模型、Token 和现行 API 价格计算，其他模型仍用相同 Token 对比。额度估算使用独立的订阅参考基准：Sol 输入 $5 / 缓存 $0.50 / 输出 $30 每百万 Token（缓存创建 $6.25），不会因 API 促销价变成 $4 / $0.40 / $20 而降低；其他模型沿用价格库参考价。日志明确记录的 Fast / priority 再按当前 ChatGPT 倍率加权，历史周期显示 Fast 条数。额度百分比来自官方快照，订阅美元折算用于比较周期，不是官方美元余额或账单。

未记录速度时默认按 1x 统计，在费用提示详情中显示数量；这表示缺少速度元数据，已有 Token 不会丢弃。未知模型倍率显示“Fast 倍率待补”。更新后历史自动补扫一次；两台机器都更新并缓存完成后，再同步全部历史，可补全另一台电脑保留的速度标记，重复同步不会增加事件数量；如果原始日志没有标记，则继续按 1x。

点 **价格设置** 打开：

- 顶部三档快速价格（GPT-5.6 Sol / DeepSeek V4.1 Flash / 小米 MiMo V2.5 Pro），可直接改单价，用于顶部费用卡对比。
- 下方按来源分组（Codex / Claude Code / ZCode / WorkBuddy / DSH）的价格预设列表；**新增价格 / 编辑价格**可自定义厂商、模型、货币（`$` / `¥` / `Credits`）与单位（`USD / 1M tokens`、`CNY / 1M tokens`、`Credits / token`），单位自动决定除数。
- 默认库包含 OpenAI、DeepSeek、小米、Kimi、智谱/Z.AI、豆包、MiniMax、千问、混元、Claude、Grok 等参考档，可直接选用或修改。
- DeepSeek V4.1 Flash / V4 Pro 的表格价格是空闲时段单价；北京时间周一至周五 `09:00–12:00`、`14:00–18:00` 自动按两倍高峰价计算，首页只显示每个模型合并后的一个金额。V4.1 Flash 当前空闲价为每百万 token：未缓存输入 ¥1、缓存命中 ¥0.02、输出 ¥4。

## 6. 套餐设置

点 **套餐设置** 打开：

- 打开时自动读取 Codex 账户套餐类型（例如 pro）；接口没有实付人民币金额、付款日期时，沿用购买记录。通用 pro 不会被当作已确认的 20x 档位。
- 点击 **添加一个月**：开始日期默认接续上次结束时间，套餐和月费沿用上次记录，空白时默认 Pro 20x / ¥1380。结束日期按自然月计算；月底和闰年自动处理。点击保存后生效。
- 表格可以修改每个套餐的起止日期、名称与金额；结束日期留空也按一个月计算。周期页面的“实际 ¥”是按时间分摊的费用，不是整月月费。
- 默认示例：`2026-05-01 - 2026-06-01 Plus ¥128`、`2026-06-02 - 2026-07-02 Pro 20x ¥1380`，可增删改。
- “从 Codex 导入”可尝试识别本地数据库中的购买记录；识别不到时保留现有设置。

## 7. 重置设置（rate limit reset bank）

点 **重置设置** 打开：

- 手动记录重置卡的获得时间、过期时间（默认按获得时间 + 30 天）、是否已用、备注。
- **同步**：使用本机 `~/.codex/auth.json` 的登录凭证向 OpenAI 账户接口拉取重置卡并写入本地（仅在你点击时联网；401 表示凭证失效）。
- 主界面“重置过期”与估算窗口会汇总展示未过期、未使用的重置卡。

## 8. 缓存详情

点顶部 **缓存详情**：

- 查看后台预热进度：按来源分类的“完成天数/总天数”、总进度条、当前任务与最近活动日志。
- 预热暂停后可点“继续”恢复；日常使用无需手动干预。

## 9. 常见问题

**Q：没有显示额度？**
额度需要能启动本机 `codex app-server`。确认已安装 Codex Desktop 或 CLI（`~/.codex/plugins/.plugin-appserver/codex.exe`、npm 安装或 PATH 中的 codex）。读取失败会自动回退到会话日志里捕获的额度记录；如果会话日志里也没有，就暂时没有数据。

**Q：费用和官方账单对不上？**
费用是按本地 token 事件 × 你选的价格预设估算的，与远端套餐额度不是同一个概念；Fast/普通模式倍率不同，混合模式只能是近似值。

**Q：导入的数据会重复吗？**
不会。导入按稳定事件 ID 和额度快照键合并，同一数据包重复导入、多包重叠导入都不会重复计数。

**Q：换电脑后设置还在吗？**
设置都存在本机 `%LOCALAPPDATA%\CodexTokenMonitor\`，不会自动迁移；用量数据可通过“数据管理”导出/导入迁移，价格、套餐、重置卡需要在新电脑重新设置。

**Q：DSH 的数据从哪里来？**
DSH 是 DeepSeek Harness，其会话日志保存在 `~/.dsh/sessions`（zstd 压缩）。监控器只读取本机会话里的 token 用量记录，不会读取你的对话内容。DSH 尚未产生任何会话时该 Tab 会显示空。

**Q：Coding Time 是怎么算的？**
把相邻 token 事件间隔 ≤ 10 分钟的视为同一活跃会话，累加各会话时长；只有事件的时间跨度，不代表真实在线时长。
