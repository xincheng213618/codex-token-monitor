# 变更记录

按日期分组的变更摘要（依据 git 提交历史，哈希可点击到对应提交）。从 2026-09-06 起，正式发布采用 `vYYYY.MM.DD` 日期版本号。

## 2026-09-19

- 额度读取去静态化：`CodexAppServerQuotaReader` 的 20s/10s 缓存、已选 CLI 命令与同步锁改为随 Codex 读取器实例持有（`UsageSourceReaders.Codex.AppServerQuota`），协议解析保持静态，行为不变。

- 测试扩面：为订阅额度折算、共享设置持久化与费用曲线计算补 11 项行为测试，费用曲线测试通过种子化用量缓存与额度时间线驱动真实计算路径。
- 文档与测试：复核旧 UI 结构检查清单并标记各项完成状态，删除额度快照缓存中 6 个无调用 helper，修正文档中上次显示文件名（v5）；修正 README/架构文档声明与实现的一致性；为重置评估（`QuotaPaceAnalyzer` 全部评级分支）与周期分析刷新范围（`QuotaAnalysisRefreshRange`）补 17 项行为测试。
- 稳定性：生产 SQLite 连接（用量缓存、额度快照、monitor-settings、共享历史）全部禁用连接池。并行测试负载下曾观察到池化句柄被释放后复用的偶发崩溃；生产 I/O 由共享闸门串行化，禁用池化无性能影响。

- 主界面范围解析移入核心：`GetSelectedRange` 的日/周/月/周期/自定义起算规则原样迁移为 `UsageRangePolicy.ResolveSelectedRange` 纯函数，配 13 项无界面行为测试；窗口行为不变。
- 周期识别器去静态化：`CodexQuotaCycleReader` 的 2 分钟周期边界缓存改为随 Codex 读取器实例持有（`UsageSourceReaders.Codex.Cycles`），周期识别纯算法保持静态；缓存失效与读取行为不变，至此读取链路不再有进程级静态可变状态。

## 2026-09-18

- Codex 读取器去静态化：`CodexUsageReader` 改为实例类，尾读器游标、子代理过滤器和额度历史缓存随实例持有；进程级共享实例经 `UsageSourceReaders.Codex` 暴露，读取行为与缓存语义不变。删除最后一个 reader 级全局测试覆盖属性 `DshUsageReader.OverrideSessionsRoot`，DSH 测试改用路径作用域。需要隔离的测试可直接构造独立读取器实例。
- 主界面用统一的 `UiEventSuppressor` 程序化更新抑制边界替换原来散落的 5 个 `suppress*` 布尔和 `initializing` 标志：控件镜像赋值改为 `using` 作用域，异常时自动释放，不再可能出现"标志卡死导致刷新入口失效"；作用域可嵌套、防重复释放，配 6 项行为测试。桌面探针同步改用按窗口持有的抑制域，主/设置/分析三组回归全部通过。

## 2026-09-17

- 主界面恢复“额度估算”入口，保留当前窗口、手动区间和历史周期表；额度曲线改为按钮按需打开独立窗口，不再随额度估算窗口启动而计算，所选周期可继续进入模型归因、消耗时间线和预测。
- 修复套餐名称仅大小写不同（如 `Pro 20x` / `Pro 20X`）时历史模型校准无法沿用、错误显示“样本不足”的问题；后续保存也复用既有套餐键，避免产生大小写重复记录。
- 模型额度标定改为汇总同套餐全部往期周期形成稳健先验，再用本期所有可计价分段做逆容量联合回归；按时间与样本量加权、抑制离群周期，并让极低占比模型保持由历史主导。

## 2026-08-20

- 自动额度刷新不再静默吞掉非取消异常；读取失败会在当前请求仍有效时提示“额度刷新失败”，窗口关闭触发的正常取消仍保持安静，避免旧额度百分比被误当成最新结果。
- 用量桶在费用计算和 SQLite 写入前统一归一化；非法价格（负数/零除数）不再产生负费用，极端费用会饱和到 `decimal.MaxValue`；检测到被篡改或损坏的日汇总时会拒绝缓存命中并回到补扫路径。
- 额度快照写入会丢弃清洗后没有任何可用窗口的行；即使旧 SQLite 把异常百分比日标记为完成，完整性预检和读取也会要求至少存在一个有效 5h/7d 百分比并触发补扫。
- 数据包导入现在拒绝清洗后没有任何可用 5h/7d 窗口的额度快照，避免把无效记录计入新增数量或写入跨设备缓存。
- 后台缓存预热器的状态回调在窗口销毁或 Dispatcher 关闭期间不会再把正常取消升级为后台任务故障；Codex app-server 退出路径即使关闭标准输入失败也会继续尝试终止精确进程树，降低超时后残留子进程的风险。
- 多个数据包并行导入时，缓存读/合并/写入阶段现在通过进程内闸门串行化，避免两个导入基于过期日汇总互相覆盖；包解析仍在进入写入闸门前完成，减少对前台缓存操作的阻塞。
- app-server 协议读取现在持续排空标准错误并在精确进程树终止后观察读取任务，避免诊断管道阻塞或留下未观察的后台读取异常。
- 主窗口关闭时会登记并有限等待后台预热、用量刷新和周期刷新任务；取消后的正常收尾会被观察，单个卡住的文件读取最多只影响短暂的退出等待，不再让任务在窗口销毁后长期悬挂。
- 修复额度明细聚合桶的边界选择：位于下一桶起点的快照不再被错误归入当前 10 分钟/日桶，避免额度曲线和 CSV 明细发生跨桶串值。
- 修复五个来源的旧缓存自愈：历史日只有汇总、没有明细时，重扫发现明细会以新扫描结果为准，不再把旧汇总和同一批日志相加造成重复统计；若日志不可用仍保留原汇总。
- 五个来源现在传播文件扫描完整性；普通日志读取异常和 DSH 截断 zstd 尾帧会保留已读结果但阻止历史日永久标记为 complete，下一次读取会继续补扫。
- Codex 额度历史扫描也传播日志读取状态；被占用或暂时不可读的 JSONL 不会再让额度日缓存错误地写成 complete，后台预热会保留该日待补扫。
- 后台缓存详情的完成天数改为回查 SQLite 的实际 incomplete 状态；读取异常但未抛错的用量、额度或时间线任务不会再被临时计入完成进度。
- 额度时间线的 incomplete 预检改为失败闭合；SQLite 不可用或查询异常时保持待处理，不再以空列表误判为“无需补缓存”。
- 后台预热结束状态不再无条件显示“全部缓存已完成”；仍有未落盘日期时会显示待补扫数量，并等待下一轮自动重试。
- 额度费用/token 上限估算统一经过溢出安全计算；极小百分比、decimal 下溢或超大 token 总量不会再让额度窗口因除法异常崩溃。
- 主窗口额度卡也复用同一套安全估算；异常或不可表示的额度上限现在显示为 `-`，不会让主界面刷新失败。
- Release 发布链路统一为真正的 win-x64 自包含单文件；项目配置、CI 冒烟检查、一键脚本和文档不再出现“命令实际依赖本机 runtime”的不一致，Core PDB 也不会混入发布目录。
- 一键发布和手动发布说明现在会先清理目标目录，并检查其中只存在主 exe；旧版 framework-dependent exe/PDB 不会继续残留在用户实际启动路径。
- 修复缓存整日范围读取绕过 `is_complete` 的问题；被中断扫描的日汇总现在会从已落盘明细重建，避免历史估算和周期统计直接采用不完整数字。
- SQLite 按日明细读取、范围明细读取和明细存在性检查现在贯穿取消令牌，并由五个来源继续向下传递；关闭窗口时不会因读取旧日大明细表而把取消吞成空结果。
- 恢复上次显示状态时统一把范围、汇总、明细和额度窗口转换为北京时间，旧版本以 UTC 保存的快照不会再把日期选择器推到前一天。
- 数据包导出的 SQLite 流式事件/额度枚举器现在直接接收取消令牌；大型导出在查询初始化、逐行读取和取消边界都能更快停止。
- 五个来源读取器的实时汇总、明细和瞬时明细入口统一把外部时间范围转换为北京时间；传入 UTC 或其他偏移时，范围元数据、日切分和缓存读取保持一致。
- 时间轴固定间隔桶构建也统一归一化输入范围，非北京时间调用不会把桶起点带成 UTC 偏移。
- SQLite 用量事件、额度快照和导入稳定键写入改为复用同一事务内的参数化命令，减少历史预热、缓存重建和大数据包导入时的命令对象分配。
- 数据包导入启用严格缓存写入：普通日志扫描仍在 SQLite 故障时降级继续，但导入不会再把被静默拒绝的缓存写入报告为成功新增。
- 额度时间线未完成日预检先统一转换到北京时间，UTC 边界输入不再漏掉范围末尾的北京时间日。
- DSH 会话读取改为按 Zstandard 帧流式解压并逐行消费，不再同时物化整份压缩文件和完整解压文本；保留多帧、跨读取缓冲区和不完整尾帧容错。
- WPF 最后显示状态在进入防抖写入队列时立即剥离明细行，避免后台持久化快照短暂持有完整查询明细。
- 事件去重改为单次字典归并，避免大范围扫描和多包导入时为每个稳定 key 创建额外分组集合；保留完整事件优先与时间排序规则。
- 各来源解析器的 token 组成相加统一使用饱和加法，极端或损坏日志不再先发生 `long` 溢出再被归一化为 0。
