# UI 与迁移结构检查

检查日期：2026-09-08。结论基于当前源码；不涉及计费算法、缓存格式或网络协议调整。

2026-09-12 更新：查询服务、刷新协调器及后台运行时已完成提取；三个分析窗口统一经过查询会话，周期分析持共享锁，费用曲线改为内存投影且不等待预热。缓存故障保留成功显示，关闭统一取消并限时等待，最后保存支持异步排空。当前结构及后续顺序见 [架构基线与迭代路线](ARCHITECTURE-REVIEW.md)；以下保留迁移阶段的历史检查记录。

## 本轮迁移边界

新增 `ResetOpportunityWindow` 与 `SubscriptionPlanWindow`，以原生 WPF 的表格、输入框和共享主题替代两份 WinForms 设置窗口。窗口负责草稿编辑、输入校验和保存前提交单元格/行；存储、额度同步、套餐识别和导入仍由现有 Core 类型完成。

重置卡同步沿用 `ResetOpportunityStore.SyncFromCodexAsync` 的原有行为：成功时立即保存服务端返回的记录；取消窗口不会撤销已同步结果。套餐导入仍只更新当前窗口草稿，保存后才生效。异步查询绑定窗口生命周期，关闭时取消并停止回写控件。

主窗口已为两个窗口设置 `Owner = this`；重置窗口关闭后无条件刷新摘要，套餐窗口仅在 `ShowDialog() == true` 时刷新。WPF 项目已移除两项旧窗体 `Compile Include` 与 `UseWindowsForms`，主程序不再调用旧 Form，两份旧 Form 源文件也已移除。

共享样式集中在 `Themes/MonitorTheme.xaml`，主窗口和设置窗口使用相同的颜色、按钮、输入框和表格资源。费用卡片已抽为 `CostCardControl.xaml/.xaml.cs`：组件只接收展示文案、数值和说明，价格计算仍在调用方。导入导出、CSV 构建和拖放处理已移入 `MainWindow.DataTransfer.cs`；它仍是同一个 `MainWindow` 类型的 partial，复用原状态与方法，目前属于分文件整理，尚未完成职责解耦。

静态行为复核确认：取消窗口不保存草稿；保存、新增、删除及套餐导入前提交单元格和行；月度新增继续检查重叠、默认沿用最近套餐和月费；账户返回通用 `pro` 时保留已记录的 5x/20x 档位。重置同步期间禁用编辑和保存，失败有提示，关闭取消异步请求后不再回写控件。实际渲染和交互验证需与这些源码检查分开记录。

## 优先结构问题

1. **MainWindow 的职责仍需逐步分离。** 主文件从审查基线约 3,050 行整理为约 2,500 行，数据交换 partial 约 490 行；刷新调度、历史缓存协调和摘要格式化仍集中在主窗口。下一步从 `MainWindow.DataTransfer.cs` 抽出不依赖 WPF 的 CSV formatter，再以现有行为测试约束刷新协调器拆分。已有 `MainWindow.DataSharing.cs`、`BreakdownGridAdapter` 和 `CostCardControl` 可作为清晰职责边界的参考。

2. **CodexUsageReader.cs 的文件名不能反映内部内容。** 审查基线约 5,500 行，同时定义 `UsageCacheStore`、`QuotaSnapshotCacheStore`、缓存 DTO、`ScanRange`、`SubagentReplayFilter` 和 `CodexUsageReader`。适合先按现有类型拆文件，保留可见性、静态状态和行为，避免同时重写查询路径。Core 已有较完整的缓存与读取回归测试，可以保护这次机械拆分。

3. **Core 仍有可清理的无调用代码。** 本轮已移除 `MainWindow` 的无调用 `AddBucketValues`、`FormatPresetColumnTitle`；实际表头逻辑保留在 `BreakdownGridAdapter`。`QuotaSnapshotCacheStore` 中复制来的 token 汇总 helpers（`Max`、`Min`、`AddBucketToSummary`、`AddEventToSummary`、`AddBucketValues`、`ToDetailBuckets`）没有活入口，`ToQuotaSnapshot` 也无调用。后续删除前以当前源码再次确认引用，避免与并行修改冲突。

4. **额度曲线存在无效的并发参数。** `QuotaCostCurveCalculator.Build` 接收 `usageReadGate` 却没有使用，两个额度窗口仍逐层传递。该路径注释已明确只读已保存明细，不应阻塞在原日志回填后面。后续应移除无效参数链或明确查询协调接口，不能为了参数名直接加锁而恢复窗口阻塞。

5. **启动行为需要持续与文档对齐。** 已修正 README 和架构文档中的旧 WinForms 依赖、共享服务不自动启动、重置卡仅手动同步等描述。实际共享监听由 `CodexDataSharingSettings.AutoStart` 控制且默认开启；首轮用量刷新后还会静默同步重置卡。后续改动这些入口时，应同步更新使用说明。

## 建议顺序

共享主题、原生设置窗口、费用卡片组件和数据交换 partial 已完成接入。后续按 CSV formatter、无调用代码、Core 类型分文件、刷新协调器的顺序推进，分别完成验证。保持现有的用量明细表、周期分析、费用口径和缓存恢复流程；不以一次全量 MVVM 改写作为迁移收尾的前提。

## 新增额度消耗时间线

周期分析图表区域提供“换算代价 / 消耗时间线”页内切换，共用周期摘要、模型归因和同一份分段表，不再打开独立的时间线窗口。`QuotaConsumptionTimelineView` 封装时间线图、紧凑摘要和范围选择；切换只改变视图及表格列的可见性，保留分段选择、排序和时间范围，不重新查询或计算周期数据。时间线横轴为真实北京时间，纵轴固定剩余额度 100%–0%，支持已有记录、最近 1 小时、完整周期及聚焦所选时段；未来无记录区域留白。时间线模式在原分段表中展示精确消耗时段、经过时间和每小时消耗的额度百分点，并按真实数值而非格式化字符串排序；切回代价图恢复原表格列。

`QuotaCycleAnalysisResult.Timeline` 保留原计算中已有的额度对齐点、真实间隔和平台；回退噪声沿用原计算的单调阈值处理。`QuotaConsumptionTimelineCalculator` 用首次跨过额度边界的时间（相邻点间插值）生成新图专用的分段副本，避免将原成本段的末尾用量回摊误算为消耗耗时；原 Bands 和成本公式不改。时间线“最快完整 5%”摘要比较已完成的固定 5% 分段，速度是包含空闲的段平均，不是瞬时速度或耗尽预测。

验证：12 项新增测试加既有回归共 293 项通过；Release 0 警告、0 错误。隔离 WPF 探针验证默认/最小尺寸、四种时间范围、原表与新图双向选择、空数据和平台线；十万点样例聚合至约 2,234 个绘制点，悬停仍按原始时间数据查找。预览使用只读提取的本周期缓存与当前显示快照，在隔离数据库内重建；末点为最后可对齐的额度记录，可能早于账户最新快照；窗口明确展示该记录时刻。探针与预览位于 `work/quota-timeline/`，未替换运行中的程序、未提交或发布。

页内切换验证：Release 构建 0 警告、0 错误。`work/quota-switch/` 的隔离 WPF 探针验证往返切换不创建窗口、不替换分析结果或表格集合，并保留选择、时间范围及数值排序；两张图均联动同一行，空数据和无消耗的平台也能切换。默认窗口与最小窗口已实际渲染；时间线有效绘图区增至约 137 px 高，最小尺寸通过正文滚动可到达明细，固定页脚保持可见。这一轮只调整 WPF 组合与显示，未改 Core 计算或真实设置。
